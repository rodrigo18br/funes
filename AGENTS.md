# AGENTS instructions

## Project structure

- `src/` - Project source code;
- `docs/` - Documentation, tasks;
- `tests/` - Unit and integration tests.

Use `uv` as dependence manager. NEVER update dependencies on yourself.

NEVER run `pytest` or `python` commands directly on the host -- always do it through `uv`.

The uv.lock file is generated by uv lock, uv sync and is committed to the repo - it contains snapshot of versions of all dependencies used for development of the repo. If at any point in time you have a conflict with uv.lock, simply delete it and run uv lock to regenerate it.

## Coding standards

* No assert in production code.
* Comment sparingly: code says what, comments say why.
* Imports at top of file. Valid exceptions: circular imports, lazy loading for worker isolation, TYPE_CHECKING blocks.
* Add new functionality alongside existing code.
* If unsure, err on the side of maintaining status quo.
* Avoid large-scale structural changes, unless explicitly requested.
* Only make changes that directly address the specific request.

## Testing

The test suite used is `pytest`. Tests should verify the logic of the search, embedding and sqlite modules in a separate way, mocking the dependencies from other modules. To test the interface code, use `pytest-qt`.

## Testing standards

* Use pytest patterns, not unittest.TestCase.
* Use spec/autospec when mocking.
* Prefer @mock.patch decorators over with mock.patch(...) context managers for patching.
* Use time_machine for time-dependent tests. Do not use datetime.now()
* Use @pytest.mark.parametrize for multiple similar inputs — consolidate tests that only differ in input/expected values into a single parametrized test.
* Use @pytest.mark.db_test for tests that require database access.
* When checking for coverage, do not filter by module, but use the flag `--cov=src/funes`.
